認証方式の耐性比較

認証方式と攻撃シナリオの組み合わせを選択すると、図解を再生できます。対象外のセルは選択できません。

阻止：不正認証を防げる不正認証成立：防げない対象外：該当する機能なし

比較の要点： パスキーは、対象となる3シナリオすべてで不正認証を阻止します。SMS受信先の乗っ取りとMFA疲労攻撃は対象外です。これは今回の代表条件における結果であり、あらゆる攻撃を防げるという意味ではありません。

各シナリオの代表条件における結果です。認証情報の漏洩：過去の入力・応答のみ取得、長期秘密なし。DB漏洩：有効なPWを取得できた想定、TOTP共有秘密も利用可能。フィッシング攻撃（AiTM型）：本人は偽サイトを正規と信じて操作し、今回の認証に必要な入力・承認を行う想定。MFA疲労攻撃：本人が単純な承認を誤って行う。番号照合などの強化策は対象外です。対象外は当該攻撃の対象となる機能がない方式です。実製品のすべての実装を保証する評価ではありません。

使い方・前提条件・参考資料

01では認証情報（パスキーを含む）は登録済みとし、登録処理は学習対象外です。01では認証方式を選んで再生します。02では耐性比較表のセルを選択して再生し、「正常系と比較」で対応する正常STEPを参照できます。「耐性比較表へ戻る」で別の組み合わせを選べます。STEPを直接選択することも可能です。PC表示では構成図と再生操作を最初の画面内に優先配置し、STEP一覧・解説・補足情報は下に表示します。同じ画面サイズ・文字サイズでは、01と02の切り替えやSTEP・条件の変更でも共通機器の位置・大きさを維持します。方式やシナリオを変更すると最初のSTEPに戻ります。

教育用の簡略モデルです。01・02の枠は青＝現在の処理、緑＝正規の認証成功・実際の拒否、赤＝攻撃者・侵害を表します。通信が未発生の場合は灰色の点線と×で表し、結果は表示文で確認します。PC・ブラウザーは正規ユーザーが操作し、PC・OSへのログインは完了済みとします。本教材は認証そのものを学習対象とし、システム全体のセキュリティは対象外です。業務サービスの認証を学習対象とし、攻撃者側の環境は攻撃シナリオでのみ表示します。パスワード入力などPC内の操作は、通信経路ではなくPCの状態で示します。業務サービスと認証サーバーは分離し、サーバーサイドWebアプリのOIDC Authorization Code Flowを共通モデルとします。初回アクセス時は双方に認証済みセッションがない前提です。state・nonce・PKCE、クライアント認証、認可判定等の詳細は省略します。パスキーのRPは認証サーバーです。実際の認証通信・攻撃・資格情報取得は行いません。TLSは正常、仕組み・耐性モードでは代替認証とアカウント復旧経路は無効、パスキーは正しく実装されたWebAuthnでUV必須とします。02では代表条件を固定し認証方式の耐性を比較します。フィッシング攻撃（AiTM型）は偽サイトを介して認証処理をリアルタイムで中継する手法です。従来型のフィッシングによる過去の認証情報の漏洩は「認証情報の漏洩」で扱い、別シナリオにはしません。追加認証とパスキーには、PCとは別のスマートフォンを利用する共通モデルを採用します。パスキーはスマートフォン上の認証器を利用し、PC内蔵認証器やセキュリティキー、端末間通信の詳細は対象外です。パスワードのみの場合はスマートフォンを使用しません。SMS・プッシュ通知の配信基盤は省略します。単純なプッシュ承認は従来型の比較対象であり、NIST SP 800-63B-4への適合を示すものではありません。番号照合はプッシュ認証の強化策であり、01・02の独立方式には含めません。同期型とデバイスバウンド型に共通する認証の仕組みを扱います。秘密鍵の同期・移行・復旧、認証ポリシーの設定差、端末のマルウェア感染、認証後のセッション窃取は対象外です。図は現在のSTEPの経路を表示します。02では未成立の経路を示します。攻撃者の赤枠は攻撃の主体を示し、攻撃の成功・失敗そのものを示すものではありません。情報枠は主な論理的な保持場所を示し、実際のデータ形式や全コピーは表しません。黄色は秘密情報や保護が必要な情報、青色は登録・検証用情報、点線は処理中または一時的な情報です。色は情報の種類を区別するものであり、青色や点線の情報が漏洩しても安全という意味ではありません。登録電話番号やアプリ登録情報も保護対象ですが、共有秘密そのものではありません。パスキーのUVはPIN等または生体によるローカル本人確認を想定し、両方が必須という意味ではありません。認証画面の取得やコード交換などは学習目的に合わせてまとめます。双方向の矢印は要求と応答をまとめた表現です。02では01と共通のSTEP名・通信ラベルを使用します。灰色の点線と×は未成立の経路です。送信後の拒否は実際の通信線と拒否の表示を区別します。認証成功時はサービス用セッションの発行まで図示します。企業内サービスの同意・認可は事前承認済みと想定します。耐性モデルは認証情報への影響に限定し、感染経路や攻撃ツールは扱いません。02の入口にある耐性比較表の対象セルを選択すると、代表条件での成否を再生します。認証サーバーDBの読み取り漏洩とサーバー完全侵害を区別します。02では、対象アカウントのIDと認証情報の対応が判明しているモデルとします。IDは認証要素ではありません。パスキーではCredential IDやuserHandleなどの識別情報と公開鍵・署名を区別します。漏洩元を特定しない場合は取得済み状態から開始し、架空の通信線は描きません。OTPは使用済みの再利用を拒否する実装を想定します（RFC 6238 §5.2、NIST SP 800-63B-4）。WebAuthnの署名・チャレンジ・UVの検証はWebAuthn Level 3 §7.2を参照。プッシュ応答の要求への紐づけはモデル上の仮定です。
